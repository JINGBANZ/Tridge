What's In My Fridge

Scan a grocery receipt, and your fridge appears on screen — every item as a prebuilt image floating on a soft background, quietly turning amber, then red, as it nears expiry. This document is the complete, one-shot build spec: design direction, every screen and interaction, data model, LLM contract, dev-environment requirements, and acceptance criteria.

Design direction

Minimal like a product shelf, playful like a game inventory

The reference is skylrk.com: a near-empty page where the product images are the interface — generous whitespace, no cards, no chrome, image-first. The home screen borrows that stance exactly: a soft ambient background and the item images floating directly on it. No tiles, no cards, no list chrome, no tab bar — a single scan button at the bottom.

Item art is a prebuilt image per item. For v1 the prebuilt set is the system food emoji rendered large (they are high-quality, cover ~120 foods, and cost nothing); the code treats art as a lookup — every item carries an id from the curated ItemID vocabulary (specific foods plus generic buckets and unknown), and Artwork maps id → emoji — so a custom illustrated sprite set can replace emoji later by dropping PNGs into the asset catalog keyed by the same ids. The game-inventory feel comes from the layout and badges, not from slot frames: fixed grid cells, a stack-count badge ("×12"), and a status pill riding the item's shoulder.

Background, not surface

A soft cool gradient (chilled-air feel) with a faint top glow — like light inside a fridge. Items cast a soft drop shadow so they sit "in" the space.

Items are the UI

Only images, names, and pills. Header is one word ("Fridge"), an item count, and a small gear for Settings. One hero action: the green scan button.

State reads at a glance

Freshness is encoded twice — the pill's color and its label ("12d", "Today", "✕ 1d"). Expired items desaturate.

Native iOS feel

SF Pro (Rounded for display), standard sheets, haptics on every consume action. No custom nav paradigms.

Screens & interactions

Four screens, one flow

ScreenContents & behavior
1 · HomeHeader ("Fridge", item count, gear icon → Settings sheet) · item grid as specced above · single floating scan button.
Tap item → Item Detail sheet.
Long-press + drag item → grid dims, scan button fades out, the two drop zones slide up: 😋 Ate it (left) and 🗑️ Tossed (right); dropping marks the item consumed/wasted with a haptic — for ×N items it decrements quantity by 1 and the item stays until 0. Releasing outside a zone cancels.
Empty state: centered ghost item + "Scan your first receipt" + arrow pointing at the scan button.
2 · ScanTapping the scan button opens VNDocumentCameraViewController (VisionKit); long-pressing it offers the source menu (camera · photo library; debug builds add a bundled sample receipt). Where the document camera is unavailable (Simulator, browser-hosted simulators) the tap falls back to the photo-library picker automatically, so the camera is an enhancement, not a requirement. On capture or photo selection: full-screen progress ("Reading your receipt…", animated receipt emoji), image is downscaled to max 1568px long edge, JPEG 80%, sent to the LLM. Errors (network / key missing / unparseable) show a friendly retry alert.
3 · Review sheetPresented sheet (see mock). Scan date + count header. Each row: art, clean name, original receipt text in small gray, qty, tappable date chip (opens compact date picker). Unrecognized items (id unknown) flagged amber with "tap to fix". Rows can be deleted (swipe) or edited (tap name). Primary button "Add N items to Fridge" saves all, schedules notifications, pops to Home where new items animate in.
4 · Item DetailSheet with large art (tap to pick different art from the prebuilt set), name field, quantity stepper, storage picker (Fridge/Freezer/Pantry), expiry date picker with source note ("Guessed by AI — tap to correct"), and a "📷 Scan date label" button → camera + on-device Vision OCR (VNRecognizeTextRequest), regex-match date formats (MM/DD/YY, DD MMM YYYY, YYYY-MM-DD, "Best by …"), accept the first plausible date (today < d < today+5y) after user confirmation. Buttons: Ate it · Tossed it · Delete.
＋ Settings sheetOpened from the gear icon (not a tab): OpenAI API key (SecureField, stored in Keychain), notification hour (default 9:00), default storage location, and a Diagnostics row that copies this session’s app logs (via AppLog/OSLog) to the clipboard for bug reports. No stats in v1.

The core loop

Shop, then scan

User taps the scan button, photographs the receipt. VisionKit auto-crops and de-skews.

LLM parses everything at once

One API call returns a curated item id, clean name, quantity, and shelf-life estimate per item. No barcode DB, no OCR post-processing.

Confirm in one tap

Review sheet fixes trust: user corrects anything odd, then "Add N items". Dates the user edits are marked userSet and never overwritten.

Live inventory

Home grid shows everything, soonest-expiring first. Pills tick down daily; notifications fire at T−2 days and on expiry day at the configured hour.

Eat or toss

Drag an item to a drop zone (or use the detail sheet buttons). Consumed items leave the grid but persist, so waste stats can be added later.

Data model

SwiftData schema

FieldTypeNotes
idUUIDprimary
nameStringclean display name ("Whole Milk")
receiptTextString?raw line from receipt ("TJ WHL MLK 1GAL")
artKeyStringan ItemID rawValue from the curated vocabulary ("milk"); Artwork resolves id → emoji (v1) or a custom image later, unrecognized keys fall back to unknown's art
quantityInt≥1; consume decrements, removes at 0
storageenumfridge · freezer · pantry; new items get the Settings default, editable per item
purchaseDateDatethe day the receipt was scanned (not read from the receipt)
expiryDateDatepurchaseDate + shelfLifeDays initially
expirySourceenumllmEstimate · userSet · scannedLabel — never overwrite userSet/scannedLabel
statusenumactive · eaten · tossed
consumedDateDate?set when status changes; kept so waste stats can be added later

Urgency is computed, not stored: daysLeft = calendarDays(now → expiryDate). Expired means end-of-day(expiryDate) < now. Persistence is local-only SwiftData for v1; the schema is CloudKit-compatible (all optionals/defaults) so sync can be enabled later without migration.

LLM integration

One vision call does receipt → inventory

Direct call to the OpenAI Chat Completions API with model gpt-5-mini (fast, pennies per receipt). The response shape is enforced server-side with a strict Structured Outputs JSON Schema — SCHEMA below, built programmatically in WhatsInMyFridge/Core/ReceiptSchema.swift and test-checked against the Swift DTOs — so replies always match the contract; the prompt carries only the content rules. Per item the LLM returns exactly: id (one of the curated ItemID vocabulary — the schema's enum makes anything else impossible), name, receipt_text, quantity, shelf_life_days. No store name, no purchase date (the app stamps the scan day), no emoji (art is resolved from id on-device), no storage guess (the Settings default applies). Unknown-item strategy is tiered: specific id → generic bucket id (fruit, vegetable, meat, …) → unknown, which the review sheet flags amber for fixing; ids added to the vocabulary later decode as unknown on older builds. The user's API key is entered in Settings and stored in Keychain — no backend for v1. Wrap it in an LLMService protocol so a proxy can replace it later.

POST https://api.openai.com/v1/chat/completions
headers: Authorization: Bearer <key> · content-type: application/json
body: { "model": "gpt-5-mini", "max_completion_tokens": 4000, "reasoning_effort": "low",
        "response_format": { "type": "json_schema",
          "json_schema": { "name": "parsed_receipt", "strict": true, "schema": SCHEMA }},
        "messages": [{ "role": "user", "content": [
          { "type": "image_url", "image_url": { "url": "data:image/jpeg;base64,<receipt>" }},
          { "type": "text", "text": PROMPT }]}] }

PROMPT (verbatim — content rules only; the JSON shape and allowed id values come from SCHEMA):

This is a grocery store receipt. Extract every FOOD and BEVERAGE item.
Rules:
- Expand abbreviations into clean, human-friendly names ("WHL MLK 1GAL" → "Whole Milk").
- Skip non-food lines: tax, totals, coupons, bags, household goods, loyalty points.
- If one line has a quantity multiplier, set quantity accordingly.
- Estimate each item's typical shelf life in days from purchase, assuming it
  is stored appropriately at home (refrigerated promptly where applicable).
- For "id", pick the closest match from the allowed values. Prefer a specific
  id; if nothing specific fits, pick a generic one (fruit, vegetable, dairy,
  meat, seafood, bakery, beverage, grain, snack, condiment, frozen).
- If a line is probably food but you cannot tell what it is, use id "unknown"
  and name "Unknown item".
  • Parsing: structured outputs guarantees schema-valid JSON, but the client stays defensive: strip Markdown code fences if present, then JSONDecoder. On decode failure (truncation, refusal), retry the call once; then surface a retry alert.
  • Image prep: longest edge ≤ 1568px, JPEG quality 0.8, before base64.
  • Unidentifiable items come back as id unknown and get the amber "tap to fix" treatment in the review sheet, never silently dropped.
  • No key set: scan button opens Settings with an inline explainer instead of the camera.

Development environment

What you need to build and run this

The short version: a native iOS app cannot be compiled on a Linux VPS. Swift itself runs on Linux, but the iOS SDK, SwiftUI, the simulator, and code signing exist only inside Xcode on macOS — Apple ships them nowhere else. So the question is where the macOS machine lives:

OptionWhat it looks likeCost / trade-off
A · Your own MacXcode 16+ on any Apple-silicon Mac (a base Mac mini is enough). Full simulator, instant iteration, deploy to your iPhone over cable or Wi-Fi.Best experience. Mac mini from ~$599 if you don't own one.
B · Rented cloud MacA macOS VM you remote into: MacStadium, Scaleway Apple silicon, AWS EC2 Mac. Run Xcode over screen sharing; your Linux VPS workflow stays for everything else.~$0.10–0.65/hr or ~$50–130/mo; AWS has a 24h minimum. Remote-desktop Xcode is usable but laggy.
C · Linux VPS + macOS CIYou (and Claude Code) write all the Swift on the VPS. GitHub Actions macOS runners compile, run the unit tests, and upload builds to TestFlight. You never touch a Mac directly.Free for public repos (macOS runners bill 10× minutes on private free tier). Iteration loop is 10–20 min per build and there's no simulator screenshot loop — fine for an agent one-shot + fix cycles, painful for pixel-level UI tweaking. Requires the $99/yr Apple Developer Program for TestFlight signing.
Realistic recommendation for your setup: write the code on the VPS, build with option C, and if the UI needs more than a couple of correction rounds, spin up a cloud Mac for a day (option B) to polish with the simulator. Swift Package structure + unit tests (parsing, urgency logic, date regex) are Linux-runnable, so most logic bugs get caught before a macOS build is ever needed.

Definition of done

Acceptance criteria for the one-shot build

  • App builds clean in Xcode for iOS 17 simulator; no third-party dependencies.
  • Scanning a real Trader Joe's–style receipt yields a review sheet with ≥90% of food lines as clean names, each with art, quantity, and a plausible future expiry date.
  • Confirming the sheet adds items to Home, sorted soonest-first, with staggered pop-in animation.
  • Items render with no background frame — art + shadow directly on the gradient; pills green ≥3d, amber 1–2d, red today/expired; expired art desaturates; app badge equals expired count.
  • Home has exactly one control at the bottom: the circular scan button. No tab bar.
  • Long-press-dragging an item dims the grid and reveals the two drop zones; dropping on "Ate it"/"Tossed" fires a haptic and updates status; ×N quantity decrements before removal; releasing elsewhere cancels.
  • Editing a date in Item Detail sets expirySource = userSet, reschedules both notifications, and survives relaunch.
  • "Scan date label" reads a printed "BEST BY 07/12/26" via on-device OCR and offers it for confirmation.
  • Notifications fire at T−2d and expiry day at the configured hour (verifiable with a short-dated test item).
  • No API key → scan routes to Settings with explanation; network failure → retry alert; malformed LLM JSON → one automatic retry.
  • Empty fridge shows the empty state; dark mode renders per the dark tokens; Reduce Motion disables the pop-in spring and drag float.
  • Unit tests pass on Linux via swift test where possible: LLM JSON parsing (incl. fenced output), urgency thresholds, date-regex parsing.
Build order for the agent: Models + Artwork lookup → AppTheme → Home grid with seeded sample data → drag-to-consume → LLM service + scan flow → review sheet → detail + notifications → OCR date scan → settings → tests.
